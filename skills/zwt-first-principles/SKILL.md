# ZWT 第一性原理拆解与重构

把问题拆到足以重新判断方案的基本事实、目标和约束，再据此提出可验证的路径。不为了显得深入而无限追溯，不为了创新而强行推翻已有方案。

## 先拆解问题

结合用户输入和相关上下文，简短界定要解决的问题，区分希望达到的结果与目前想到的手段；保留用户明确的目标和边界。随后清楚区分四类内容：

1. **已经确认、无法绕开的基本事实。** 列出与决策有关的稳定事实、必要关系或条件，说明依据与适用范围。区分用户提供的情况和已独立核实的证据；“大家都这样做”、个人解释或未经验证的因果关系不是基本事实。证据不足时明确留空或标为待验证，不凑出确定结论。
2. **习惯性接受、尚未验证的假设。** 揭示方案依赖但未证实的前提，例如把一种实现方式当成唯一办法。说明哪些假设最影响结论；未知不等于错误，不能仅因为未验证就反向断言它不成立。
3. **真正想实现的目标。** 说明最终想改变什么，以及怎样观察到目标实现；把目标与代理指标、偏好和手段区分开。推断出的意图要标明，不以“真正目标”为名替用户换目标。
4. **现实中的资源与约束。** 识别相关的时间、预算、能力、现有资产、依赖和风险边界；区分当前必须遵守的硬约束、可协商条件与暂定假设。可改变不等于已经获准改变，不能在推导时悄悄移除现实约束。

主题明确时先分析，不先发整套问卷。缺少具体问题时只问必要的澄清；关键证据不足时给出条件性判断或少量关键追问，不虚构事实填补缺口。

## 从事实、目标和约束重新推导

- 暂时不以行业惯例、竞品做法或现成方案为出发点，先明确达到目标必须满足的条件，再寻找在现有约束内实现这些条件的可行方式。用可核查的依据和关键关系解释路径为何有望成立，不从分类清单直接跳到熟悉的方案。
- 放下惯例不等于丢弃已验证知识、专业证据或安全要求。推导后可以重新比较和采用现有方法；若原方案已经符合基本条件，明确保留，不强求一条完全不同的“新路线”。
- 优先选择假设更少、成本与复杂度相称且可验证的路径。存在真实分歧时才给有区别的备选，并说明取舍；不预设必须自研、重写、颠覆行业或扩大项目范围。

## 最后输出四项结论

在四类拆解及必要的推导说明之后，依次整理：

1. **原方案中只在修补表面的部分。** 指出具体措施改变了什么表象、未触及哪个关键机制，以及判断依据。没有原方案时明确“未提供原方案，无法评价”；证据不足时保留判断，原方案合理时如实说明，不编造缺陷或把所有局部改进都贬为表面修补。
2. **从基本事实重新推导出的新路径。** 给出推荐方向及其关键依据，说明它如何满足目标和约束；可以是对原方案的保留、简化或重组，不以新奇程度评价质量。
3. **这条路径成立的前提。** 列出真正影响可行性的依赖、条件和未验证假设，指出最脆弱或最可能改变结论的一项；说明条件不满足时结论如何变化，避免把推导出的可能性当成已证实效果。
4. **验证它的第一步。** 优先检验影响最大的关键不确定性，提出一个低成本、范围可控的具体动作，说明观察什么、什么结果支持或反驳关键前提，以及之后继续、调整还是放弃。未知的数值门槛标为待定或建议，不冒充已知标准；不直接扩展成完整实施计划。

## 讨论与作用边界

- 本技能提供分析、建议和验证设计，不自动修改代码、文件、配置、数据或外部系统，也不自动执行验证实验。认可结论不等于授权实施；用户明确授权转入实施时，按其最新要求处理。
- 只在当前轮次显式调用时应用本流程；后续未再次调用时不强制沿用其结构或讨论限制。保留已确认的信息，篇幅与问题复杂度相称，不额外套用双向论证、连续问诊或完整产品规划。
